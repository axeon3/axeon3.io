firestore-pqc-stack · Architecture & Wire Spec

FIPS 203 (ML-KEM-768) + X25519 + AES-256-GCM · FIPS 204 (ML-DSA-65) + Ed25519

Unified 4-layer monorepo combining Cloud KMS Terraform, FastAPI backend, Rust WASM crate, and TypeScript browser bindings.

1. infra/terraform → backend

Provisions HSM/Software ML_KEM_768 & ML_DSA_65 keys with PREVENT deletion locks and exports CryptoKeyVersion IDs.

2. wasm-client → web → backend

Browser encapsulates DEK & signs raw UTF-8 HTTP body bytes via WASM; FastAPI verifies conjunction auth and decapsulates via Cloud KMS.

Hybrid Key Derivation & AEAD Binding

Combines post-quantum ML-KEM-768 (FIPS 203) with classical X25519 ECDH via HKDF-SHA256 (salt=None, info="firestore-hybrid-pqc-v1"), binding the Firestore document path as AES-256-GCM AAD to prevent cross-document relocation attacks.

Envelope Field Byte Size Encoding / Role
ml_kem_768_pub 1,184 B Server encapsulation key fetched from Cloud KMS
kem_ciphertext 1,088 B Base64 in JSON; implicit rejection yields pseudorandom 32B on tamper
x25519_ephemeral_pub 32 B Base64 in JSON; per-document ephemeral X25519 public share
hkdf_ikm 64 B pq_ss (32B) || classical_ss (32B) → 32B AES-256 DEK
nonce 12 B 96-bit WebCrypto CSPRNG nonce
ciphertext + tag N + 16 B AES-256-GCM payload authenticated with aad = doc_path

Strict Conjunction (AND-Combiner) Authentication

Both classical Ed25519 (64 B) and post-quantum ML-DSA-65 (3,309 B, FIPS 204) must validate independently over the canonical transcript. Both private keys are stored as compact 32-byte seeds in browser IndexedDB.

HTTP Header Format / Size Validation Rule
X-Key-Id string Resolves Ed25519 (32B) + ML-DSA-65 (1,952B) public key bundle
X-Sig-Alg ed25519+ml-dsa-65 Constant-time equality check; bound inside signed transcript
X-Timestamp unix seconds Enforces |now - ts| ≤ 60s skew window
X-Nonce 32-char hex (16B) Single-use CSPRNG nonce rejected on replay
X-Hybrid-Signature 3,373 B (URL-Safe B64) ed25519_sig (64B) || ml_dsa_65_sig (3309B)
